Here are a few workarounds:---##### **Option 1**: If the word is in a <br> `data-*` attribute```lang-html<ul>	<li data-word="apple">I like apple</li>	<li data-word="banana">I like banana</li></ul>``````lang-cssli[data-word$="apple"] {	color: red;}```>This selects `<li>` elements whose `data-word` ends with `"apple"`.---##### Option 2: If the word is wrapped in a `<span>````lang-html<ul>	<li>I like <span class="fruit">apple</span></li>	<li>I like <span class="fruit">banana</span></li></ul>``````lang-cssli:has(span.fruit:last-child:contains("apple")) {	color: red;}``` `:has()` and `:contains()` are not widely supported (especially in Firefox), and `:contains()` is not part of the CSS spec — it’s jQuery-only. So this won’t work in pure CSS today.---##### JavaScript fallback (if you need to match text content)```lang-jsdocument.querySelectorAll("li").forEach(li => {	if (li.textContent.trim().endsWith("apple")) {		li.style.color = "red";	}});```>>>>>Would you like a reusable HTML+CSS+JS demo that highlights `<li>` items ending in a specific word? I can help with that too.To highlight only whole-word matches of `"highlight"` inside any `<li>`, and visually emphasize just the word (not the whole list item), you can use JavaScript to:1. Match the word as a whole word using a regular expression.2. Wrap the matched word in a `<mark>` tag (or a custom span) for styling.---##### HTML```lang-html<ul>	<li>This should highlight</li>	<li>This should not</li>	<li>Another highlight here</li>	<li>Highlighting is not a match</li></ul>```##### CSS```lang-cssmark {	background-color: gold;	font-weight: bold;	padding: 0 2px;}```##### JavaScript```lang-jsdocument.querySelectorAll("li").forEach(li => {	const regex = /\b(highlight)\b/gi;	if (regex.test(li.textContent)) {		li.innerHTML = li.textContent.replace(regex, '<mark>$1</mark>');	}});```##### What this does:• `\b` ensures whole-word boundaries (so `"highlight"` matches, but `"highlighting"` does not).• `gi` makes it case-insensitive and global (matches all instances).• `replace()` wraps each match in a `<mark>` tag, which browsers style by default (or you can customize it).--->>>>>Would you like this bundled into a ready-to-preview HTML file for Textastic or browser testing?Here’s a complete HTML demo that highlights the whole word “highlight” inside any `<li>` element on the page.
