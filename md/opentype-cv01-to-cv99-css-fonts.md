They are primarily controlled using the CSS properties font-feature-settings or font-variant-alternates. [^1][^2][^3][^4][^5]Using `font-feature-settings`This low-level property is widely supported and uses the direct OpenType four-character tag. The value is a comma-separated string of feature tags. [^6][^7][^8][^9]```lang-css.char-variant-01 {  /* Enables character variant 01 */  font-feature-settings: "cv01";}.char-variant-02 {  /* Enables character variant 02 */  font-feature-settings: "cv02";}.multiple-variants {  /* Enables multiple specific variants */  font-feature-settings: "cv01", "cv03", "cv05";}```Using `font-variant-alternates`This property is part of a newer, more semantic CSS module. It uses the `character-variant()` function, which can be more readable. [^1][^10][^11][^12][^13]```lang-css.char-variant-01 {  /* Enables character variant 01 */  font-variant-alternates: character-variant(1);}.char-variant-multiple {  /* Enables multiple variants */  font-variant-alternates: character-variant(1, 3, 5);}```Defining custom names with `@font-feature-values` [^14]You can also use the `@font-feature-values` at-rule to assign a custom, more descriptive name to a character variant index, improving maintainability. [^1][^15][^16]```lang-css@font-feature-values Font Name {  @character-variant {    'slashed-zero': 1; /* Maps the name 'slashed-zero' to cv01 */  }}.slashed-zero-text {  font-family: "Font Name";  font-variant-alternates: character-variant(slashed-zero);}```### Important Notes: - These CSS rules only work if the specific font you are using has the corresponding `cv01` to `cv99` OpenType features built into the font file by the designer. - Browser support is generally excellent for font-feature-settings, while font-variant-alternates has good, but slightly less universal, support. - You can check if a specific font supports OpenType features using online tools and demos like the Complete CSS Demo for OpenType Features.
